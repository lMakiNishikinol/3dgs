# 小程序 3D 模型查看器需求与技术调研

## 1. 文档目的

本文将 3D 模型查看器的业务需求、格式调研、技术方案、尺寸测量规则和实施建议统一整理，作为后续在微信小程序中开发模型查看器的需求基线。

目标能力：

- 在小程序中查看 GLB 和 PLY 模型；
- 为后续扩展 OBJ、STL、FBX、点云和大型场景格式预留架构；
- 支持模型旋转、缩放、平移、适应屏幕和恢复视角；
- 自动计算模型几何尺寸；
- 支持两点测量和可读的比例尺展示；
- 明确区分“几何尺寸”和“可信的物理尺寸”。

## 2. 范围与非目标

### 2.1 首期范围

首期支持：

1. `.glb`：产品模型、建筑模型、带材质模型和动画模型；
2. `.ply`：三角网格、带顶点颜色的模型和点云；
3. 基础交互：旋转、缩放、平移、适应屏幕、恢复视角；
4. 模型信息：文件大小、顶点数、面数、包围盒尺寸、单位状态；
5. 测量功能：选择两个点并显示距离；
6. 点云显示：点大小、颜色模式和点/面显示切换。

### 2.2 后续范围

根据模型来源和性能需求再扩展：

- OBJ、STL：通用兼容和打印模型；
- FBX、USD/USDZ：复杂场景和动画；
- LAS/LAZ、E57、PCD：工程点云；
- 3D Tiles：城市、地图、BIM 和超大场景；
- Draco、Meshopt、KTX2 等压缩和纹理扩展；
- 分块加载、LOD 和服务端预处理。

### 2.3 非目标

首期不做完整建模编辑器，不支持修改顶点、拓扑、材质或动画制作，也不承诺直接兼容所有厂商私有扩展。

## 3. 常见 3D 模型格式

| 类别 | 格式 | 特点 | 查看器优先级 |
| --- | --- | --- | --- |
| Web/实时渲染 | glTF/GLB | 运行时友好，支持网格、材质、纹理、动画；GLB 可单文件打包 | 首期 |
| 通用交换 | OBJ | 简单、兼容性好，但场景和材质能力有限 | 后续 |
| 动画/工业交换 | FBX | 支持复杂场景、骨骼和动画，格式相对封闭 | 后续 |
| 场景交换 | COLLADA/DAE | XML 格式，功能完整但文件较大 | 低 |
| Apple/AR/影视 | USD/USDZ | 适合复杂场景和 AR | 后续 |
| 扫描/点云 | PLY | 支持顶点、面、颜色、法线，也可以只存点云 | 首期 |
| 三角面/打印 | STL | 主要保存三角面，材质和单位信息弱 | 后续 |
| CAD/工程 | STEP、IGES、JT | 精确几何和工程数据，通常需要专用解析器 | 低 |
| BIM | IFC | 包含建筑构件和语义信息 | 低 |
| 工程点云 | LAS/LAZ、E57、PCD、XYZ | 面向测绘、激光扫描和科研数据 | 后续 |
| 超大场景 | 3D Tiles | 支持城市、地图和大规模分块加载 | 后续 |

推荐把 GLB 作为默认的模型交换和展示格式，把 PLY 作为扫描模型和点云格式。

## 4. Three.js 与微信小程序可行性

### 4.1 结论

可以使用 Three.js 完成 GLB 和 PLY 查看。微信小程序有 `threejs-miniprogram` WebGL 适配项目，可以将 Three.js 绑定到小程序 Canvas 节点中。

核心组件：

- `GLTFLoader`：GLB/glTF 2.0；
- `PLYLoader`：ASCII 或二进制 PLY；
- `DRACOLoader`：Draco 压缩网格；
- `KTX2Loader`：压缩纹理；
- `OrbitControls`：轨道相机交互；
- `Raycaster`：模型点击、选点和测量。

### 4.2 需要注意的兼容性

微信小程序适配版 Three.js 的版本可能落后于当前 Three.js。当前项目适配仓库说明其基础版本为 `0.108.0`，因此最新版 Loader、压缩格式和材质扩展不能默认认为可以直接运行。

实现时需要：

1. 锁定项目使用的 Three.js 适配版本；
2. 在微信开发者工具和真机上分别测试；
3. 对 GLB、PLY、压缩 GLB、带纹理 GLB、点云 PLY 建立样例集；
4. 评估 Android 和 iOS 的 WebGL、内存与纹理兼容性；
5. 失败时给出格式、纹理、压缩解码或文件大小的明确提示。

### 4.3 建议的统一加载架构

```text
模型文件
  ↓
文件下载 / 本地读取为 ArrayBuffer
  ↓
按扩展名和文件头识别格式
  ↓
GLTFLoader / PLYLoader / 其它 Loader
  ↓
统一转换为 THREE.Object3D
  ↓
统一处理相机、坐标系、缩放、包围盒、拾取、标尺和性能
```

建议不要让业务页面直接依赖某一个 Loader，而是定义统一接口，例如：

```text
loadModel(source) -> ModelAsset

ModelAsset:
  object
  format
  unit
  unitConfidence
  boundingBox
  vertexCount
  faceCount
  hasTexture
  hasAnimation
  isPointCloud
```

## 5. 模型查看器常见痛点

### 5.1 单位不可靠

同一组坐标数字可能被不同软件解释为米、厘米、毫米或无单位。导出软件还可能在导出时额外缩放模型。

### 5.2 坐标系和朝向不一致

不同格式或软件可能使用不同的上方向、前方向、左右手坐标系和原点位置。查看器需要支持自动纠正或手动调整。

### 5.3 大模型性能问题

顶点过多、ASCII PLY、超大纹理、材质过多都会导致加载慢、内存上涨、渲染卡顿甚至崩溃。点云需要特别关注点数、点大小和 GPU 上传成本。

### 5.4 材质和纹理兼容性

常见问题包括纹理丢失、透明效果异常、法线错误、金属度/粗糙度不一致，以及压缩纹理或第三方扩展无法解码。

### 5.5 初始视角不合理

模型可能过大、过小、偏离原点或被相机裁剪。必须提供“适应屏幕”和“恢复视角”，并根据模型包围盒自动设置相机距离和近远裁剪面。

### 5.6 PLY 语义有限

PLY 主要保存顶点、面和附加属性，不是完整的场景描述格式。通常不包含场景层级、实例、动画、预设相机和标准化单位，也可能只有点云而没有面。

### 5.7 测量结果容易被误解

查看器可以准确计算坐标距离，但若单位未知，不能把结果直接标成毫米或米。界面必须展示单位来源和可信度。

## 6. 尺寸与标尺可行性

### 6.1 GLB

GLTF 2.0 规定线性距离单位为米，并允许节点包含平移、旋转和缩放变换。因此可以在加载后遍历场景节点、应用世界变换并计算整体包围盒，得到模型宽度、高度和深度。

需要注意：GLB 通常不是直接保存“模型宽度”字段，而是从顶点坐标和节点变换推导尺寸。如果导出软件的单位设置错误，计算结果仍然会错误。

结论：GLB 可以实现自动尺寸和物理标尺，但尺寸可信度取决于导出流程。

### 6.2 PLY

PLY 通常包含 `x`、`y`、`z` 坐标，可以计算包围盒和两点距离。但 PLY 标准没有统一的单位元数据要求，坐标可能代表米、毫米、厘米或无单位数值。

结论：PLY 可以自动计算“坐标单位下的几何尺寸”，但不能仅凭文件可靠推断物理单位。

### 6.3 任意格式

应采用以下单位优先级：

```text
文件内明确单位
  > 业务系统模型元数据
  > 用户上传时选择的单位
  > 格式默认约定
  > 未知单位，仅显示 units
```

对于 PLY 或其它没有可靠单位的格式，建议要求上传时填写：

- 单位：米、厘米、毫米、英寸或未知；
- 模型类型：三角网格或点云；
- 上方向和前方向；
- 是否需要缩放或旋转；
- 是否包含顶点颜色。

建议保存旁车元数据，例如：

```json
{
  "unit": "mm",
  "upAxis": "Y",
  "frontAxis": "Z",
  "scale": 1,
  "coordinateSystem": "right-handed"
}
```

## 7. 标尺和测量功能设计

### 7.1 自动尺寸信息

模型加载后显示：

- 宽度；
- 高度；
- 深度；
- 顶点数；
- 三角面数；
- 是否带纹理；
- 是否带动画；
- 是否为点云；
- 单位及单位可信度。

### 7.2 两点测量

用户点击模型上的两个点后：

1. 使用 Raycaster 获取两个交点；
2. 将交点转换为世界坐标；
3. 计算两点的欧氏距离；
4. 绘制两点之间的连线；
5. 在连线中点显示结果和单位；
6. 提供清除和重新测量操作。

计算关系：

```text
显示距离 = 世界坐标距离 × 单位换算比例
```

### 7.3 自适应比例尺

比例尺应根据相机当前缩放级别动态选择 1、2、5、10 等易读刻度，例如：

```text
1 mm → 2 mm → 5 mm → 1 cm → 2 cm → 5 cm → 10 cm
```

比例尺应明确标注单位来源：

- `真实尺寸：mm`；
- `模型单位：units`；
- `单位由用户指定：mm`；
- `单位未知，结果仅供参考`。

## 8. 推荐的分阶段实施计划

### Phase 1：基础查看

- 接入小程序 Three.js WebGL Canvas；
- 加载 GLB；
- 实现旋转、缩放、平移；
- 实现适应屏幕和恢复视角；
- 展示基础加载进度和错误信息。

### Phase 2：PLY 和模型信息

- 接入 PLYLoader；
- 支持网格 PLY 和点云 PLY；
- 计算包围盒；
- 展示顶点数、面数和尺寸；
- 增加点大小、点/面显示和颜色模式。

### Phase 3：测量和单位

- 增加模型单位元数据；
- 增加两点测量；
- 增加自适应比例尺；
- 增加单位可信度提示；
- 支持测量结果复制或保存。

### Phase 4：性能和格式扩展

- Draco/Meshopt/KTX2；
- 模型压缩和服务端预处理；
- LOD、降采样和分块加载；
- OBJ、STL 或其它业务所需格式；
- 超大点云或 3D Tiles。

## 9. 验收标准

### 功能

- GLB 可以正常加载并显示材质；
- PLY 网格和点云可以分别显示；
- 旋转、缩放、平移操作流畅；
- 可以恢复视角和适应屏幕；
- 可以显示模型包围盒尺寸；
- 可以完成两点测量；
- 单位未知时不会错误显示为米或毫米。

### 兼容性

- 微信开发者工具可运行；
- 至少覆盖一款 Android 和一款 iOS 真机；
- 覆盖小模型、中等模型和大模型；
- 覆盖 ASCII PLY、二进制 PLY、带颜色 PLY 和无面点云；
- 覆盖普通 GLB、带纹理 GLB 和带动画 GLB。

### 性能

- 加载过程有进度或状态反馈；
- 大文件失败时给出可理解的原因；
- 模型切换时释放 Geometry、Material、Texture 和缓存资源；
- 不因重复进入页面造成 WebGL 资源持续增长。

## 10. 最终决策

建议采用以下产品规则：

1. GLB 和 PLY 作为首期格式；
2. GLB 默认按米解释，但仍显示“单位来自格式规范”的状态；
3. PLY 默认显示 `units`，上传或业务数据提供单位后再显示物理单位；
4. 自动计算几何尺寸对 GLB 和 PLY 都支持；
5. 真实标尺必须依赖可信单位，不能仅根据坐标数值猜测；
6. 通过统一 `ModelAsset` 和 `ModelMetadata` 层为后续格式扩展做准备；
7. 首期重点验证小程序适配版 Three.js、PLY 解析、真机性能和资源释放。
